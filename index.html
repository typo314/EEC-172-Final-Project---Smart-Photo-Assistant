Project Description

Description

For this project, we designed and built an interactive embedded camera system that allows a user to remotely trigger an image capture, display the captured image locally, and send image analysis data to the cloud. The main idea of the system is to combine sensing, embedded processing, and cloud communication in a standalone device.

A user can press a button on a remote control to trigger the system. When the signal is received, the system captures an image using a camera module. The captured image is then displayed on an OLED screen so the user can see the result.

At the same time, the system performs a simple brightness analysis on the image by measuring how dark different parts of the image are. The brightness data is then sent to AWS through the CC3200 WiFi module. AWS processes the data and sends a notification email that contains the brightness values of different regions of the image.

Design

Functional Specification

When the device is powered on, the system begins in the Start state and automatically goes into the initialization state where it initializes the required hardware components, including the IR receiver, camera module, Arduino interface, and OLED display.

It then enters the waiting for remote signal state, it will wait for any valid remote signal from the universal remote controller. If it doesn’t it loops back into the state until a valid signal is received. Then the state switches to the picture taking state where it takes a picture of whatever the camera is pointed at.

From the camera, the microcontroller must process the information and display it on the OLED screen. Then send the data from the CC3200 to the user’s email so the user can know the data on how dark/bright the room is, this stalls here until there is a valid wifi signal it can send the data through.

Then it goes back to the waiting for the remote signal state where it will wait until the valid signal is given once again and start the picture taking process and data analysis is gone through again.

System Architecture

It starts by having the universal remote send the signal to the IR Signal Sensor, these two parts tell the camera when to take the picture for dark/brightness analysis. The arduino is used for powering and initializing the camera module and taking the data in for further analysis. The CC3200 microcontroller works as a conduit for these components, it interfaces with the IR Sensor, detecting when the user wants their picture taken. It also interfaces with the arduino via UART, giving the camera data to the CC3200 to be stored (as the Arduino has no storage) and analyzed by the CC3200. The CC3200 also interacts with the ADAfruit OLED screen, where it displays the picture onto the OLED screen for the user to see how the picture looks. Lastly, over the WiFi, it sends information on darkness and brightness levels of the image taken. Then it is sent to the user’s email where the data is shown to the user for them to decide if they need to increase the brightness for their photos.

Implementation

The IR signal sensor is connected to the CC3200 through GPIO input pin and requires a resistor and capacitor for implementation for the CC3200 board to read. Our code reads the signals down and up signal lengths, and based on a 26 long binary number associated with the signal high/low behavior it will tell the CC3200 what button on the universal remote has been pressed.

The OV7670 camera module uses the I2C protocol with the Arduino, giving the RGB565 2 bytes per pixel data to the arduino which is immediately siphoned off to the CC3200 for frame storage. The code for the arduino was found online, but was modified to suit the requirements of frame size and color adjustments, and to be sent over the UART serially. The baud rate for the UART was 500000 baud to meet the camera’s 500000 baud rate receiving data.

The CC3200 reads the data off the UART from the Arduino and converts that data from RGB565 to grayscale for lower usage of our limited storage on the CC3200. It then pixel by pixel accounts for levels of darkness of each pixel, and sends it to the ADAfruit OLED for the user to see. The camera module will output a 160x120 picture through the UART, but with the limited size we only kept 160x104 for ease of storing and to reduce the time of collecting pixels, because we do not want the UART to overflow otherwise we will distort the image. The CC3200 does the calculations for what percentage of the photo is in each level of dark, we used eight stages of dark as that was how many colors we had for the OLED, so you can compare the results to what you see.

The ADAfruit OLED Screen uses the SPI protocol to communicate with the CC3200, the SPI pins are connected to the coordinating SPI pins on the CC3200 decided in the sysconfig tool, pixel by pixel we parsed through the array using the draw pixel command to update each pixel so we can see the image on the screen. The data is also sent through AWS IoT from the CC3200 to the cloud, and when the shadow updates, sends that data to the user through email.

Challenges

The main challenge was originally trying to get the camera module to work on the CC3200, it had major power and clocking issues and the imminent deadline approaching, our solution was to have the Arduino which we had used to test the camera module to interface with the CC3200 board.

The next problem was that the grayscale version of the camera just returned static, which we had first encountered when the arduino wasn’t implemented and thought the CC3200 communication was incorrect, and switched to arduino powering only to find only RGB worked.

Originally the product was supposed to interface directly with the user’s phone, which is why a bluetooth module was bought, but that raised issues with Apple's inter-app communication policies and caused us to pivot to a different solution of messaging and causing the image taking on the phone.

When we tried to implement the messaging through SMS, it had notified me that we could not send a message without a certain phone number type, and would take two weeks for me to receive. So we pivoted to an email based messaging camera automization, but as emails are not automatically notified like SMS are, it proved inoperable at that moment making us pivot to taking the photo with just the camera and sending that to the cloud.

The next challenge was with amazon lambda/rekognition, we could not figure out how to implement it into the CC3200 in time, so our next solution was to send the image in a word are kind of way similar to what you would see on the OLED, but that proved to be too large of an image of 160x104 pixels and a byte of information for each pixel. So without any of that going for us, we switched to just general information about pixel brightness/darkness.

Future Work

In the future, the system would send data over to AWS Rekognition and identify the face whether or not if the eyes are open and if they are smiling, if both of those checks are satisfied then it would send the picture to the person’s email, providing them with a good photo.

The next possible future implementation would be getting it off of the Arduino, and only having the Arduino be used for powering the clock and 5V/3.3V power sources, as it is too weak for it to interface with it originally. To be completely off of the arduino we could use the camera booster for the CC3200, which would supply the camera with enough power according to the forum posts online.

We could also get a better camera, and switch off of the bulky remote provided to us by having the camera be setup to take pictures periodically and when all of the people within the picture are smiling and have their eyes open, so it's a generally good photo, then the OLED would show that it was a good photo by pulling from the AWS shadow.

The last future implementation would be to clean up the wiring, design a PCB, solder the board together and 3D print a box for it to make it look generally cleaner.
